Stand up a complete design system from zero — don't jump to components. Run it as a consultation, not a paint job.

**Phases:**
1. **Understand the product** — who uses it, the core job, the brand posture, and where it lives (web/mobile/desktop). Get the one sentence that defines what "good-looking" means *for this product* before proposing anything.
2. **Research the landscape** — name 3–5 reference products in the space, what each does well, and the convention users already expect. Decide where to meet the convention and where to take a deliberate creative risk.
3. **Propose the system** — a single coherent proposal covering: aesthetic family, typography (display + body pairing + scale), color (palette + semantic tokens, light/dark), layout model, spacing/density scale, elevation, component shape language, and motion tone. Every value is a token, not a one-off.
4. **Preview before building** — show the fonts and palette rendered together (and ideally a realistic product mockup of one real screen) so direction is confirmed on something concrete, not described in the abstract.
5. **Hand off** — write the agreed system to `DESIGN.md` so implementation derives from it in one coherent pass.

**Rules:** propose ONE opinionated direction with rationale (plus the risk you took and why), not a menu of safe options. Anti-slop: no generic gradients, no symmetric template layouts, no empty filler cards, no emoji icons. Source: github.com/garrytan/gstack
